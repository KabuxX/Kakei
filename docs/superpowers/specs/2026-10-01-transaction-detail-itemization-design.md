# 取引詳細の店名・支払方法・品目リストの設計

## 目的と範囲

Kakei の利用者が支出の詳細を開き、どこで、どう支払い、何をいくらで購入したかを確認できるようにする。新しい支出を登録する際にこれらの情報を入力・保存できるようにする。詳細画面は引き続き閲覧と削除だけを提供し、編集機能は加えない。

対象は既存のアプリ内画面である。画面の見た目は `DESIGN.md`、一般的な UX は `design-system/household-budget-app/MASTER.md` と `ui-ux-pro-max`、詳細画面の既存の遷移と削除は `2026-10-01-transaction-detail-design.md` に従う。収入の登録項目と詳細表示は現状のままとする。

## データと互換性

既存の取引レコードに、支出用の `merchant`（店名・取引先）、`paymentMethod`、`items`（`{ name, amount }` の配列）を追加する。支払方法は `cash`、`credit_card`、`e_money`、`bank_account` の4値とし、画面にはそれぞれ「現金」「クレジットカード」「電子マネー」「銀行口座」と表示する。品目の金額は円単位の正の整数とし、カテゴリは引き続き取引全体に一つ付ける。

保存先は既存の `kakei-transactions-v1` を維持する。新項目のない既存レコードは有効なまま読み込み、移行や既存レコードへの架空の値の補完はしない。新項目だけが壊れた保存データでは、取引自体を消さず、その項目を未登録として扱う。品目配列の合計が保存済みの取引金額と異なる場合も、品目だけを未登録として扱う。新規支出は店名・取引先と支払方法が必須、品目リストは任意である。既存のサンプル支出の一部には、金額が一致する具体的な店名・支払方法・品目を設定して機能を確認できるようにする。

## 新規取引の登録

支出を選んだときだけ、既存の追加ダイアログに「店名・取引先」「支払方法」「品目」を表示する。店名・取引先は空白を除いて必須とする。支払方法は未選択状態から4つのいずれかを明示的に選ぶ。品目は行の追加と削除ができ、各行は名前と金額の組で入力する。行を作った場合は片方だけ空のまま保存できない。

品目がない支出では、従来の金額欄に1円から999,999,999円までの整数を入力する。品目が1行以上ある支出では、有効な各行の金額の合計を取引金額へ自動反映し、金額欄には計算結果を表示する。合計が999,999,999円を超えた場合は保存できず、理由を示す。最後の品目行を削除すると金額欄は直接入力に戻り、品目追加前に手入力していた金額を復元する。収入では既存の入力欄と金額入力を使う。

入力エラー時はダイアログを開いたまま該当欄に理由を示す。保存時は完成した次の取引配列を先に `localStorage` へ書き込み、成功した場合だけ画面内の配列を更新してダイアログを閉じる。保存失敗時は入力内容を保持して通知し、登録成功として扱わない。

## 詳細表示

支出の詳細では、既存の金額・内容・日付・カテゴリに続けて「店名・取引先」「支払方法」をラベル付きで示す。その下に「品目」の見出しと、品目名・金額を行ごとに並べた一覧を置く。品目の合計は取引金額と一致する。新項目のない支出では店名・支払方法を「未登録」、品目欄を「品目は登録されていません」と表示し、値を推測しない。収入の詳細には支出専用の欄を出さない。削除操作は従来通りページ下部に置く。

デスクトップでは読みやすい本文幅に収め、スマートフォンでは一列に並べる。品目名が長くても金額が読め、横スクロールや下部ナビゲーションによる遮蔽が起きないようにする。ラベルと金額は色だけに依存せず、キーボード操作とスクリーンリーダーの読み順を保つ。

## CSV と既存の動作

月別 CSV の既存列に「店名・取引先」「支払方法」「品目」を追加する。品目は名前と金額の組を保持できる JSON 文字列として一つのセルに出力し、項目がない取引では空欄にする。文字列の CSV エスケープと表計算ソフトの数式として解釈されないための既存の対策を維持する。

詳細 URL、一覧への復帰、別タブでの更新、削除、集計、検索とフィルターは既存の動作を保つ。集計には品目ごとの金額を重複加算せず、取引金額を一度だけ使う。

## 実装境界と確認条件

- `front/index.html` と `front/styles.css`: 追加ダイアログの支出専用欄、品目行の操作、詳細の表示領域とレスポンシブ表示。
- `front/app.js`: 入力の切り替え、品目合計、保存、詳細表示、CSV 出力。必要な純粋な計算・検証は小さな補助モジュールに分け、ブラウザ操作なしで確認できるようにする。
- 取引詳細の URL と削除の既存の責務は維持し、無関係な画面の構成を変えない。

完成時には、新しい支出を品目あり・なしの両方で登録でき、再読み込み後も詳細が一致することを確認する。品目の合計、未完成行、上限超過、保存失敗、旧形式の取引、別タブ更新、CSV の新列を確認する。デスクトップとスマートフォンで詳細と追加ダイアログを確認し、ダッシュボードの最初に表示月と収支が見えることも確認する。
