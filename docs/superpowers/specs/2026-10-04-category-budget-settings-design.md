# カテゴリ別予算の設定

## 目的と合意した範囲

概要画面からカテゴリ別の予算を設定し、合計を月全体の予算として使えるようにする。ユーザーが最終的に選んだ設定単位はカテゴリ別であり、月全体だけを設定する案は採用しない。

予算は毎月共通。選択した月の支出に対して共通の予算を適用するため、変更は過去の月の表示にも反映される。月別の履歴・予約変更は持たない。

成功条件は、6カテゴリの金額を保存でき、月全体の予算・残額・使用率・カテゴリ別の進捗が一致し、ページ再読み込みやサーバー再起動後も設定が維持されること。

## 現状

- `front/src/lib/dashboard.js` の6カテゴリには固定の予算額があり、合計は250,000円。
- `front/src/pages/Dashboard.jsx` は月の予算とカテゴリ別の予算を表示するが、編集操作はない。
- バックエンドには取引・軌跡などのSQLite保存とAPIがあるが、家計予算の保存機能はない。
- この画面はアプリ内の概要画面。見た目は `DESIGN.md`、情報順序はダッシュボードのページ指定、残りのUXはMASTERとui-ux-pro-maxに従う。

## 採用する操作

「月の予算」カードの見出し付近に、文字付きの「予算を設定」ボタンを置く。既存の財布アイコンは装飾として扱い、アイコンだけを操作の入口にしない。

ボタンで編集ダイアログを開く。通常のカードに入力欄を並べる方法も比較したが、6カテゴリの編集と合計確認をまとめ、閲覧時の密度を維持できるダイアログ方式を採用する。

ダイアログには次を表示する。

1. 見出し「予算を設定」と「毎月共通の予算です。変更はすべての月に適用されます。」という説明。
2. 食費・住まい・日用品・交通・娯楽・その他の6つの金額入力欄。各欄にラベルと円の単位を付ける。
3. 入力に合わせて更新する「月の予算」の合計。無効・未入力の欄がある間は、確定した合計として表示しない。
4. 「保存」「キャンセル」と閉じる操作。

開くと保存済みの金額を入力欄に入れる。入力途中では概要画面の予算を変更しない。「保存」の成功時にだけ予算状態を更新し、ダイアログを閉じ、「予算を保存しました」と通知する。「キャンセル」・閉じる・Escapeは未保存の変更を破棄する。追加の確認ダイアログは設けない。

保存中は二重送信と編集・閉じる操作を無効にし、保存中と表示する。失敗時はダイアログと入力内容を残し、原因と再試行方法を表示する。

## 金額と計算

各カテゴリの金額は0〜999,999,999円の整数とする。空欄・負数・小数・数値以外・上限超過は保存できない。フロントで入力を検証し、APIでも独立して検証する。APIは文字列・booleanを整数として受理しない。

初期値は現行の金額を引き継ぐ。

| カテゴリ | 初期予算 |
| --- | ---: |
| 食費 | 60,000円 |
| 住まい | 90,000円 |
| 日用品 | 25,000円 |
| 交通 | 25,000円 |
| 娯楽 | 30,000円 |
| その他 | 20,000円 |

月全体の予算は6カテゴリの合計で、独立した金額として保存しない。残額は「合計予算−選択月の支出」。収入や取引フィルターは予算計算を変えない。

予算が正の値の場合、使用率は支出÷予算で計算し、進捗バーは0〜100%に収める。超過時は金額でも状態を伝える。

カテゴリまたは合計の予算が0円の場合は次の通り。

- 支出0円：進捗0%、予算0円を表示。
- 支出あり：進捗100%と超過状態を表示し、超過額を明示する。無限大の割合は表示しない。

どの場合もNaN・InfinityがCSSやアクセシビリティ属性に入らないようにする。

## 保存とAPI

SQLiteに `category_budgets` テーブルを追加する。カテゴリ名を主キー、金額を範囲制約付き整数とする。スキーマ作成時に6カテゴリの初期値を不足分だけ挿入し、既存の設定を上書きしない。取引や軌跡のテーブル・データは変更しない。

予算の読み書きは取引の初期化と独立して利用できる。

- `GET /api/budget`：保存済みの全カテゴリを返す。
- `PUT /api/budget`：全6カテゴリを一度に検証・保存し、保存結果を返す。
- リクエスト・レスポンスの形は `{"categories": {"食費": 60000, "住まい": 90000, "日用品": 25000, "交通": 25000, "娯楽": 30000, "その他": 20000}}`。
- カテゴリ不足・未知のカテゴリ・無効な金額は400。エラーに対象フィールドを含める。
- 6カテゴリの更新は単一トランザクション。失敗しても一部だけ新しい金額にしない。
- 既存のローカルアクセス制御と同一Originの書き込み制約を適用する。
- 複数画面からの保存は最後に成功した保存を採用する。競合確認機能は追加しない。

役割は小さなモジュールに分ける。バックエンドは予算の検証・DB操作・HTTPルートを分離し、既存のStoreとアプリ組み立てから接続する。フロントは予算API・読み込み保存用フック・編集ダイアログを分け、AppからDashboardへ状態と操作を渡す。新しいダイアログは `front/src/components/budget/` に置く。

`dashboard.js` のカテゴリ名・色は表示用の定義として維持し、固定予算の計算をサーバーから取得した値に置き換える。

## 読み込み・エラー状態

取引と予算は独立して読み込む。予算取得中や初回の取得失敗でも、選択月と取引から計算できる収支・支出内訳・取引一覧は利用できる。

予算の取得前は予算に依存する金額・割合を未取得として表示する。取得失敗を固定の初期値で隠さず、予算カードに再試行できるエラーを表示する。保存済みの予算を読み込めるまで編集を開始させない。

保存失敗時は最後に読み込みまたは保存が成功した予算を概要画面に維持する。入力エラーは該当欄に表示し、通信・DBエラーはフォーム全体に表示する。

## アクセシビリティとレスポンシブ

既存のネイティブdialogとフォームの見た目に合わせる。開く際は最初の入力へフォーカスし、閉じると「予算を設定」に戻す。キーボードで全操作を利用でき、フォーカス表示を維持する。

ラベルと入力欄を関連付け、エラーを `aria-describedby` と `aria-invalid` で対応付ける。保存・エラー・完了の状態を読み上げ可能にする。電話幅では入力欄を縦に並べ、数値キーボードを使え、横スクロールを発生させない。必要な場合はダイアログ内を縦スクロールできる。操作領域は44px以上を確保する。

概要画面の既存のカード順序を維持する。デスクトップと電話幅の最初の表示で、選択月と収支を引き続き確認できるようにする。

## 検証と完了条件

- バックエンド：初期値、更新、Store再作成後の永続化、既存設定を保つ移行、0円、境界値、欠落・未知カテゴリ・無効型・無効金額、更新の原子性、HTTPとアクセス制御。
- フロント：保存済み金額の入力、入力中の合計、保存成功後の反映、キャンセル、保存中の制御、取得と保存の失敗・再試行、入力エラー、カテゴリ予算と合計が0円の場合の表示と計算。
- 既存のフロント・バックエンドテストとフロントの本番ビルドを実行する。
- ブラウザでデスクトップと電話幅の最初の表示、ダイアログの入力・保存・キャンセル、キーボードフォーカス、再読み込み後の維持を確認する。
- 保存操作を含む検証は隔離した一時DBを使い、ユーザーの実データをテスト目的で変更しない。

## 対象外

月別予算、予算の履歴、カテゴリの追加・削除、収入予算、Agentによる予算変更、専用の設定ページは追加しない。
