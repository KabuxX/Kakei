# 取引日時の分単位精度設計

## 目的と範囲

取引の記録日時を日付だけでなく分まで扱い、フロントの追加フォームと取引詳細、バックエンド API、SQLite の値を一致させる。新規取引では入力した日時を保持する。過去の取引や初期取込データのように日付しかない場合は、仮時刻を生成して分単位の形式へ揃え、仮の値であることを明示する。

対象は、フロントの取引追加フォーム・詳細表示・月変更処理・CSV出力、バックエンドの日時検証・初期取込・保存・スキーマ移行、月次集計と軌跡の取引参照である。軌跡イベント自身の日付と時刻の形式は変えない。

## データ契約

取引の `date` は `YYYY-MM-DDTHH:mm` 形式のローカル日時とする。秒、UTC オフセット、タイムゾーン変換は含めない。日時表示・並べ替えに同じ値を使うため、日付部分は `date[:10]`、月部分は `date[:7]` で取得できる。

取引には `timeEstimated` を追加する。API の一覧・単一取得・作成レスポンスに必ず boolean として含め、SQLite では `time_estimated` として保存する。新しい日時付き入力は `false` とする。日付だけの既存値を補完したものは `true` とする。この値はサーバーが設定し、作成リクエストからクライアントが指定するものではない。

日付だけのレコードを一括補完するときは、同じ日付の取引を ID の昇順で安定して並べ、それぞれに異なる仮時刻を割り当てる。1件だけなら12:00とする。複数件が840件以下なら、08:00から21:59までの分を ID 順に均等配置する。841〜1,440件なら00:00から23:59までに均等配置する。同日1,440件を超える場合は重複時刻を作らず、取込または移行をエラーにする。日付は変えない。移行と再取込の結果が再現可能になるよう、同じレコード集合には常に同じ時刻を割り当てる。

## バックエンドと移行

新規作成 API は分単位の `date` を必須とする。形式、実在する年月日、00:00〜23:59の時刻を検証し、不正な値は既存と同じ日時フィールドの 400 エラーで返す。初期取込では従来データとの互換性のため `YYYY-MM-DD` も受け付け、取込バッチ内の日付ごとに仮時刻を割り当てる。サンプルデータ置換も同じ規則を使い、繰り返し実行時に同じ値になる。

SQLite の `transactions` に `time_estimated` を追加する。起動時のスキーマ確認で、日付だけの既存行を検出し、同日グループごとに `date` と推定フラグを補完する。`items_json` を持つ旧スキーマの移行経路でも、品目移行と日時補完を同じ SQLite トランザクション内で行う。更新中に失敗した場合はスキーマと元データの両方をロールバックする。日時がすでに分単位の行は再補完しない。

## フロントエンド

取引追加フォームの日付欄を、可視ラベル「日付と時刻」を持つ `datetime-local` 入力に置き換え、分単位で送信する。初期値は端末の現在日時を分で切り詰めた値とする。日時検証エラーは入力欄の直下に表示し、既存のエラー時フォーカス移動を保つ。

取引詳細では、日本語の年月日と24時間表記の時刻を表示する。`timeEstimated` が `true` の場合は「時刻は仮設定」と表示し、入力された時刻と区別する。数字には既存の数値スタイルを使い、長いラベルや値が狭い画面で横にはみ出さないようにする。

日時の組み立て、日付部分の取得、ローカル日時の表示は共有ヘルパーに集約する。フォーム送信後に表示月を選ぶ処理も `YYYY-MM-DDTHH:mm` を安全に扱う。

## 集計、軌跡、CSV

月フィルターは `date[:7]`、日付の表示と週別分類は `date[:10]` を使う。取引の新しい順のソートは、同一形式のローカル日時文字列の辞書順を使い、分まで反映する。

軌跡データは従来どおり日付単位とする。フロントの軌跡モデルとバックエンドのサンプル参照検証では、取引日時の `date[:10]` と軌跡日の `date` を比較し、時刻の追加後も同日の参照を保つ。

CSV の `date` 列には分単位の値を出力し、新しい「時刻の精度」列には推定値で「仮設定」、それ以外で「入力時刻」を出力する。これによりエクスポート後も時刻の出どころを識別できる。

## 確認条件

- 日付だけの既存 DB が一度だけ移行され、元の日付、全取引、品目、初期化状態を保つ。推定時刻は同日内で重複せず、推定フラグが設定される。
- 移行失敗時に元のスキーマとデータが残り、再起動やサンプル再置換で時刻が変わらない。
- 日付だけの初期取込データが仮時刻付きで保存され、新しい取引は分単位の日時と `timeEstimated: false` で保存・取得される。
- 不正な年月日や時刻は部分保存されず、日時フィールドのエラーとして返る。
- 取引詳細は日時と仮設定状態を示す。月次・週別集計と軌跡参照は分単位日時を含む取引で正しい。
- CSV は分単位日時と時刻精度を出力する。
- デスクトップ幅とスマートフォン幅で日時入力と詳細表示が読め、横スクロールが発生しない。
