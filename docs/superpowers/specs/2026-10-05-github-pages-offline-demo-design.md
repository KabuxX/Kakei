# GitHub Pages用・東京のローカル地図付き閲覧DEMO

## 目的と合意事項

GitHubからリンクを開くだけで、Kakeiの現在の画面と記録を確認できる展示版を作る。ユーザーはGitHub Pagesでの公開、現在の会話履歴とレシート原本も含めること、閲覧専用、外部APIを呼ばない地図を選択した。

初期データは現在のSQLiteから一度エクスポートする。確認時点では取引41件、軌跡13日・訪問38件・地点13件、会話3件・メッセージ8件、レシート原本2件、予算6カテゴリ。既存の9月固定JSONだけへ置き換えない。以後、通常版のDBが変わっても公開DEMOを自動更新しない。

地図の範囲は東京都の本土（23区と多摩）。島しょ部は含めない。Google Mapsをローカル保存する案と、地図表示時にGoogle APIへ通信する案は採用しない。

成功条件は、PythonサーバーとAPIキーなしでGitHub Pages上の概要・軌跡・会話履歴・レシートを閲覧でき、東京の地図と軌跡を外部サービスへのリクエストなしで表示できること。

## 構成

既存のReactアプリを再利用し、ビルド時の`demo`モードでデータ通信、地図、書き込み操作の可否を切り替える。通常版のAPI、SQLite保存、Google Maps地図と既存の開発用mockモードを維持する。

- `dev:demo`：公開DEMOと同じsnapshotとブラウザ内mock APIをローカルで確認する。
- `build:demo`：GitHub Pages用成果物を`front/dist-demo/`へ出力する。
- 通常の`build`：これまで通り通常版を`front/dist/`へ出力する。

DEMOのデータ・レシート・地図・スタイル・文字描画・アイコン・JavaScript/CSSは、同じ公開サイト内の静的ファイルとして配信する。CDN、Google、Mapbox、OpenAI、地図タイル提供者への自動リクエストは行わない。出典などの外部リンクは、閲覧者が明示的に開く場合に限って利用できる。

アプリをGitHub Pagesから最初に読み込む通信と、同じサイト内の静的ファイルの取得は必要。「外部API不要」は、端末が完全に無通信でも初回起動できるという意味ではない。PWAやオフライン再起動用Service Workerは今回追加しない。

## Snapshotの作成と公開データ

読み取り元のDBをSQLiteのバックアップ機能で一貫した一時snapshotにし、そのコピーから表示用データと原本をエクスポートする。ユーザーのDBに対してスキーマ変更、期限切れ処理、削除、地図検索を実行しない。取引・軌跡・予算・会話・変更案・レシートの参照関係を維持する。

公開物は表示用JSONと必要な原本だけにする。SQLiteファイル、`.env`、キー、認証情報、処理リース、内部ツール入出力のログは含めない。会話本文、日時、取引と品目、予算、軌跡の訪問・移動情報、保存済み変更案の差分と状態、レシート原本を保持する。

原本は元のMIMEタイプとbytesを保った静的ファイルにする。取引詳細と会話のレシート参照をそのファイルへ接続する。保存時点の状態を表示し、閲覧時の日付が進んでも原本を削除したり、公開データを書き換えたりしない。レシートのプレビュー・別タブ表示を利用できるようにする。

エクスポート時刻、データ件数、原本のハッシュ、snapshotの版をmanifestへ記録する。JSON形式、参照先、訪問ID、時系列順、予算、原本ハッシュを検証し、壊れた参照や読めない原本があれば公開ビルドを失敗させる。エクスポート時の件数が設計時の観測値と異なる場合は差分を報告し、公開対象を黙って増減させない。

## Google由来の地点の扱い

現在の地点13件のうち2件はGoogle Places由来。Googleの地図や取得済みのPlaces生応答・期限付き座標cacheをオープン地図へ転用して配布しない。通常版のDBは変更しない。

DEMOでは、同じ店舗をレシート・店舗公式情報・利用可能なオープン住所／地図データなどGoogle以外の根拠で照合し、独立した出典と座標を持つDEMO用地点にする。訪問ID、取引との対応、店と日時は維持する。単にproviderや出典ラベルだけを変更する方法は禁止する。

元の会話本文と保存済み操作の履歴は維持する。Googleの検索結果を動的に読み込む表示はDEMO用の静的地点情報へ切り替え、過去の検索履歴とDEMOの地図用座標の出典を区別する。Googleの生応答からしか得られない追加情報は同梱せず、その情報が表示に必要なら独立した根拠を得る。

座標を独立に確認できない地点は、捏造せず「DEMO用の位置は未確認」と表示し、訪問と取引は残す。マーカーとその地点へつながる線・距離は未確定として扱う。完了報告で対象と理由を明示する。独立照合によって座標や概算距離が通常版とわずかに異なることは許容する。

## ブラウザ内mock API

DEMO専用の小さな通信モジュールが、既存APIと同じ表示用レスポンスをsnapshotから返す。通常版は既存のHTTP通信を続ける。全ページにデータ選択の分岐を散在させず、API境界で切り替える。

必要な読み取りは、初期化済み状態、取引一覧と詳細、予算、軌跡日付一覧と指定日、取引先住所の参照、Agent状態と会話一覧・詳細、保存済み変更案、取引のレシート一覧。レシートbytesは静的URLから配信する。地図設定はローカル地図を選択するDEMO設定にする。

mock APIの返却値を呼び出し側が変更してもsnapshotは変わらない。存在しない記録は404相当、書き込みは`demo_read_only`の403相当、対応していない読み取りは明示的なエラーを返す。HTTP APIへのフォールバックはしない。ページ内の直接fetchやGoogle地点読み込みも取りこぼさない。

データ読込に失敗した場合は、その画面の再試行を提供する。失敗を9月固定サンプルや空の家計で隠さない。閲覧に取引の初期化POSTや会話作成POSTを必要としない。

## 閲覧専用UI

このDEMOはアプリ内画面。情報順序はページ指定、見た目は`DESIGN.md`、一般UXはMASTERを適用する。展示用のマーケティングページや新しいランディング画面は追加しない。

トップバーに小さく「DEMO・閲覧専用」を表示し、既存のカード配置を維持する。概要では選択月と収支がPC・電話幅の最初の表示に現れる。初回表示月はsnapshotの最新取引の月にし、公開後に暦が進んでも空の月から始めない。月変更、検索・フィルター、取引詳細、CSVダウンロードは利用できる。

追加・編集・削除・予算保存・住所変更・変更案承認／却下・会話作成／削除・送信・レシート添付を無効にする。意味のない押せない操作を大量に残さず、書き込み用の入口はDEMOでは非表示にし、必要な箇所に閲覧専用の説明を置く。編集／削除URLへ直接移動しても入力・保存へ進めず、対応する閲覧画面を案内する。

Agent Chatは会話一覧から保存済みの会話を選んで表示する。保存済み変更案、レシートの読み取り結果、軌跡作成結果を閲覧できる。送信欄と新規会話の作成を起動条件にしない。保留中の変更案も閲覧用として扱い、後から承認できるようにはしない。会話がないsnapshotでも明確な空状態を表示する。

通常版の編集・保存やAgentの動作は維持する。DEMOは通常版のlocalStorageキーを読み書きせず、実データを復元・初期化しない。

## ローカル地図

MapLibre GL JSと、OpenStreetMap由来のProtomapsベースマップを使う。Protomapsの公開アーカイブから、東京本土を覆う範囲を事前に切り出したPMTilesを同梱する。OSMの通常タイルサーバーから一括ダウンロードしない。

範囲は初期案として経度138.90〜139.95、緯度35.45〜35.95の矩形とする。東京都の本土を覆うかと、全DEMO訪問地点を含むかを取得時に検証する。この矩形に含まれる近隣地域の表示は許容し、東京都の行政界に厳密に切り抜く要件は設けない。地図移動をこの保存範囲内に制限し、範囲外のタイルを取得しない。

タイルはzoom 0〜14を基本とし、表示の拡大は最大zoom 16まで許容する。道路、鉄道、水域、主要な地名を日本語で表示する。写真・Street View・3D地形は追加しない。地図アーカイブは50 MiB以内を上限にする。範囲または必要な表示を満たせない場合は黙って範囲を縮めず、具体的な容量・表示上の制約を報告する。

スタイル、必要なspriteと文字描画用資源も同梱する。PMTilesを同じサイトから読み、GitHub PagesのRange応答で表示できることを確認する。Range未対応のプレビューでも、サイズ上限を守った全体読み込みからローカルでタイルを取り出せるようにする。外部URLへ切り替える代替処理は設けない。

現在の番号付き訪問ピン、選択中の色、区間ごとの色分け、日付切り替えに応じた表示範囲調整、ピンと時系列の相互選択を維持する。線と距離は実経路ではなく既存の概算表示を維持する。時系列は地図の下で内容をスクロールする既存構成を維持する。

地図準備中・読み込み失敗・WebGL不可・位置未確認の場合も時系列と取引の閲覧を維持する。読み込み失敗では再試行を提供する。出典とライセンス表記は地図と資料に残す。

## 公開と再現性

GitHub PagesのプロジェクトURL（`/Kakei/`）に対応し、ロゴ、地図、レシート、リンク、CSSと遅延読み込みのURLをbase pathに従わせる。既存のhashルーティングを維持する。

GitHub ActionsでDEMOをビルドしてPagesへ配信する。ビルドはコミット済みのsnapshotと地図を使い、ユーザーのSQLiteや`.env`を必要としない。CIが地図提供者・Google・OpenAIへデータ照合しに行かない。依存はlockで固定する。

地図の取得元、版、範囲、zoom、ライセンス、ファイルハッシュと再生成手順を記録する。DEMOデータの再エクスポートは明示的な手動操作とし、起動や通常のビルドで公開データを変更しない。

READMEにDEMOのURL、閲覧専用であること、同梱データと地図の範囲、ローカル確認とビルド方法を記載する。通常版とDEMOの起動・成果物を区別する。

## 検証と完了条件

- エクスポート：実DBを変更しないこと、一貫したsnapshot、件数と参照整合性、日時・品目・予算・会話・原本の保持、原本ハッシュ、Google生応答・cacheと秘密情報を公開物に含めないこと。
- mock API：既存レスポンス契約、読取成功・404・データ不良、返却値の独立性、全書き込みの拒否、ネットワークへのフォールバックなし。
- UI：概要の収支と全取引、取引詳細と原本、13日分の軌跡、3会話の本文・差分・レシート表示、閲覧専用の操作制限と直接URL、最新記録月からの初期表示。
- 地図：全保存日、0／1／複数地点、選択と日付変更、範囲の制限、同梱日本語表示、Range対応と全体読み込み、準備中・失敗・再試行・WebGL不可時の時系列表示。
- 配信：`/Kakei/`配下で、ロゴ、地図、レシート、遅延読み込み、直接hash URLが動くこと。外部ネットワークを遮断しても同じサイト内の資源だけで閲覧できること。
- 通常版：フロント・バックエンドの既存テスト、通常版ビルド、DEMOビルドを実行し、通常版の地図・API・保存の切り替えが壊れていないこと。
- ブラウザ：1440pxと375pxで最初の表示、ナビゲーション、取引と予算、軌跡、会話と原本を確認する。キーボード操作、focus、横あふれ、スクロールも確認する。
- 公開後：GitHub PagesのURLでDEMOの読取と地図を確認し、実際のリクエスト先に外部APIが含まれないことを確認する。

## 対象外

DEMOでの編集や保存、模擬Agentの新規応答、AIによるレシート解析、外部の店舗検索、全国地図、島しょの地図、航空写真、完全無通信での初回起動、新しいマーケティング画面。
