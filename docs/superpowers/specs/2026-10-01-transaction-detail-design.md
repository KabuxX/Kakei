# 取引詳細ページの設計

## 目的と範囲

Kakei の利用者が、取引履歴から一件を開き、記録した内容をすぐ確認できるようにする。詳細画面は確認を主目的とし、削除だけを補助操作として提供する。表示する情報は既存の `title`、`amount`、`date`、`type`、`category` の5項目とする。編集、メモ、支払方法は今回の範囲に含めない。

対象はログイン不要の既存のアプリ内画面である。公開向けページの構成や文言は適用しない。見た目は `DESIGN.md`、一般的な UX は `design-system/household-budget-app/MASTER.md` と `ui-ux-pro-max` の関連指針に従う。

## 画面と情報の順序

取引履歴では取引名を詳細へのリンクにし、ホバー時とキーボードフォーカス時に操作可能なことを示す。行内の削除ボタンは詳細画面の削除操作に集約する。取引名と金額は一覧でも読めるままにする。

詳細画面には、上から次の順に配置する。

1. 「取引履歴へ戻る」リンクと「取引詳細」の見出し。
2. 収入または支出の種別、符号付きの金額、取引内容。金額が最も目立ち、種別は文字でも示す。
3. 日付とカテゴリをラベル付きで表示する情報欄。
4. 「取引を削除」操作。主情報から十分に離し、危険な操作として明示する。

サンプル取引には、詳細内でも「サンプルデータ」と表示する。データにない項目を空欄や推測値で補わない。デスクトップでは本文を読みやすい幅に収め、スマートフォンでは1列に配置する。既存のアプリナビゲーションを保ち、画面上部の情報が下部ナビゲーションに隠れないようにする。

## URL と遷移

既存の `front/index.html` 内で、ダッシュボード表示と詳細表示を切り替える。詳細の URL は `#transaction/<encodeURIComponent(id)>` とし、再読み込みや直接アクセスでも該当取引を表示する。既存の `#transactions` などのアンカーは引き続きダッシュボードの対象セクションを開く。

一覧から詳細へ進む際は、検索語、種別フィルター、表示月、スクロール位置を保持する。ブラウザの戻る操作は元の一覧状態へ戻す。画面の「取引履歴へ戻る」リンクも一覧へ戻し、一覧から遷移した場合は保存した位置とフォーカスを復元する。直接アクセスした場合は取引履歴セクションへ戻す。詳細表示へ移った後は見出しへフォーカスを移し、キーボードとスクリーンリーダーの現在位置を明確にする。

## データと削除

詳細は既存の `transactions` 配列と `localStorage` の保存形式をそのまま読む。新しい保存項目や移行処理は不要。URL の ID に対応する取引が存在しない場合は「取引が見つかりません」と表示し、取引履歴へ戻るリンクを示す。別タブで保存内容が変わった場合も、開いている詳細を再評価する。

削除では対象の内容を示す確認ダイアログを開く。承認後に対象を除いた配列を保存し、保存成功時だけ画面と集計に反映して一覧へ戻し、完了を通知する。保存失敗時は詳細と元データを保持し、保存設定を確認するよう通知する。キャンセル時は何も変えない。

## 実装境界

- `front/index.html`: 一覧から詳細へのリンクと、詳細・未発見状態の表示領域を追加する。
- `front/app.js`: URL の解釈、表示切替、取引データの表示、一覧状態の復元、削除の保存処理を担当する。
- `front/styles.css`: 既存の紙白、雲色の面、墨色の文字、丸みを使い、詳細表示とスマートフォン幅を整える。

画面用の別 HTML ファイルや外部ライブラリは追加しない。

## 完成条件

- 一覧の取引から詳細を開くと、5項目が元データと一致する。
- 詳細 URL の直接表示、再読み込み、ブラウザの戻る操作が働く。
- 一覧へ戻ったとき、表示月、検索語、種別フィルター、スクロール位置が保たれる。
- 存在しない ID と別タブで削除された ID に対して、未発見状態と戻る導線が表示される。
- 削除の確認・キャンセル・保存成功・保存失敗で、データと画面がそれぞれ設計通りになる。
- キーボードだけでリンク、戻る、削除を操作でき、フォーカスが見える。収支種別は色だけに依存しない。
- デスクトップとスマートフォン幅で情報が読みやすく、横スクロールや下部ナビゲーションによる遮蔽がない。
