# 地点検索の稼働環境反映

## 原因

2026-10-03 23時台の「2026年10月2日の取引記録によって、軌跡を作って」は旧バックエンドで処理されていた。サーバーの作業ディレクトリはmainで、mainのHEADは3404db6。Web検索・Mapbox移行と住所検索改善はfeat/web-place-searchの077cd29に留まっていた。

本番の最新提案にはGeoapify由来の「福岡市」候補（経度130.4017509・緯度33.5898988）が保存され、店舗を特定できていないと返信していた。検索履歴テーブルに検索記録はなく、さらに古い実行コードがプロセスに残っていた。

## 対応

- mainへfeat/web-place-searchをfast-forwardで統合。
- SQLiteバックアップ後、フロントをビルドし、Uvicornをmainから再起動。
- 本番DBのコピーで同じユーザー依頼を実AgentRunnerに渡して検証。本番には会話・提案・軌跡を追加していない。
- 最初の検証ではモデルがcountry_code=jpの根拠に駅名を渡し、地域矛盾と判定された。promptに「fieldの指定値と引用値を一致させる」「駅名から国コードを推論しない」「根拠がなければ任意の地域指定を省略する」「自分の引数の誤りと利用者の地域矛盾を区別する」を追記した。
- 修正後の検証では、最初の店名検索の結果が空でも目印を加えて再検索し、Web調査→住所抽出→Mapboxが完了。軌跡案1件が返った。
- promptの追加修正を読み込むため、バックエンドを再起動した。
